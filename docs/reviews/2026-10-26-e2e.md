# Tallus end-to-end code review

Reviewed on 2026-10-26 at commit
[`cca32d23d06a1e57ad1d193ae07b3418cfe95660`](https://github.com/String-sg/marking/commit/cca32d23d06a1e57ad1d193ae07b3418cfe95660).

The app has material correctness and privacy defects across startup, assessment,
teacher review, and publication. Resolve the P1 findings before using these paths
with real student work. This change introduces Spec Kit and review documentation;
it does not apply application fixes or certify production readiness.

## Scope and evidence

Reviewed the local launchers, browser interface, FastAPI routes, SQLite persistence,
PDF/DOCX/roster ingestion, subject marker registry, OCR/marking/annotation pipeline,
teacher approval, reports, analytics, and Google Classroom integration. Three
independent reviews covered API/data, marker processing, and browser/launcher code.
Findings were cross-checked with isolated SQLite tests, deterministic model/Google
mocks, synthetic PDFs, and Chromium probes using the actual HTML and JavaScript.

No real student data, OAuth account, live model inference, or Classroom grade
publication was used. Windows desktop/WebView2 packaging and a real mobile tunnel
were reviewed statically, not run on this macOS host. Browser bug reproductions
used mocked HTTP responses; a separate synthetic HTTP integration probe exercised
the server orchestration. Neither establishes real handwriting accuracy.

## Prioritised findings

P1 means fix before relying on the affected workflow. P2 means an important defect
that needs correction in the next iteration. Conditions and limits appear per finding.

### R01 [P1] A clean application cannot start, and the test suite cannot collect

[`pdf_processor.py:54`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/pdf_processor.py#L54)
uses `Optional` without importing it. Importing the module raises `NameError`,
transitively preventing the server from importing. Once bypassed for diagnosis,
`doc_parser.py` also references `List` without importing it. `numpy` and
`python-docx` are required by code but omitted from `requirements.txt`; Excel roster
support additionally needs `openpyxl`. Declare runtime/dev dependencies and verify
fresh installation, app import, and collection without injected globals.

### R02 [P1] Failed Chinese essay evaluation invents a passing score

[`chinese_essay.py:422`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/markers/chinese_essay.py#L422)
defaults to content 19 and language 18. A timeout or invalid model result leaves
those scores and generic feedback in place. The compression block at lines 485–489
also replaces valid zeros with 19/18. Both offline evaluation and an explicit
zero/zero response returned `success=true`, 37/60, 61.7% on synthetic work. Preserve
valid rubric scores and keep failed evaluation ungraded and visibly incomplete.

### R03 [P1] Missing rubric questions disappear from the assessment denominator

[`marker_engine.py:839`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/marker_engine.py#L839)
aligns global rubrics by iterating extracted answers and does not add unmatched
scheme questions. A two-question, four-mark assessment with only Q1 extracted
returned 2/2, 100%, A*, rather than retaining the missing two marks. This affects
General and Science through shared alignment. Keep the authoritative question set
and distinguish a blank answer from failed extraction.

### R04 [P1] Model errors can become completed extraction or student grades

[`general.py:267`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/markers/general.py#L267)
accepts a JSON object without grading fields and records zero/incorrect with no
evaluation error. A successful transport carrying `{"message":"Output incomplete"}`
returned a genuine U grade and zero failed questions.
[`base.py:125`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/markers/base.py#L125)
only fails when all questions fail: one timeout yielded a successful 50% assessment.
The step wrapper drops the failure count, and the pipeline's completion heuristic
uses feedback/grade presence, so ordinary retries can skip unresolved marking.
Failed OCR similarly returns a successful question containing
`[Page extraction error / timeout]`. Validate response structure and persist
explicit per-stage/per-question completion and retry state.

### R05 [P1] Empty assignment selection can erase the previous student's grades

[`app.js:1826`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/static/js/app.js#L1826)
calls an empty-state renderer that leaves `currentSubmission` and approval controls
active while removing question cards. Chromium reproduction: open submission 51,
select empty assignment 2, click Approve. The UI posted `/api/grading/51/approve`
with `questions:[]` while displaying assignment 2. The backend replaces all question
rows. Clear active context and disable mutations; also reject stale/empty reviews
that would overwrite existing assessed work without explicit intent.

### R06 [P1] An empty assignment batch widens to other assignments

[`submissions.py:1193`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/api/submissions.py#L1193)
falls back to all assignments when an explicit assignment yields no eligible IDs.
A request for assignment 1 with no work processed submission 200 in assignment 2.
The assignment rerun endpoint can reach the same branch. Distinguish absent scope
from an explicitly empty result and return zero work for the latter.

### R07 [P1] Automatic matching can attach a script to a same-name student in another class

[`db.py:483`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/db.py#L483)
matches exact names without class scope; ingestion callers also omit the class
argument. Two Jordan Lees in classes A and B reproduced a class-B request resolving
to class A. Scope candidate sets by trusted identity/class and surface ambiguity
instead of accepting the first name match.

### R08 [P1] Save and approval discard question grounding

[`grading.py:9`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/api/grading.py#L9)
omits page/location metadata from the review model, and the frontend payload omits
it too. Persistence deletes and reinserts all questions, defaulting missing pages
to 1 and boxes to `[]`; question-level annotations are omitted from inserts.
A real save changed page 3 / box `[10,20,30,40]` to page 1 / `[]`. Subsequent direct
marking loses its source evidence. Preserve unchanged evidence server-side and
round-trip the complete validated representation.

### R09 [P1] Downloading an approved report revokes approval

[`app.js:3404`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/static/js/app.js#L3404)
unconditionally saves a draft before export. The draft endpoint persists
`review_ready`, replacing `approved`. Merely using Report PDF therefore changes
assessment status and approved-only analytics. Separate read-only export from
editing, or preserve approval for unchanged content and visibly invalidate it only
when the assessment actually changes.

### R10 [P1] OCR and report fields render stored text as executable HTML

[`app.js:2382`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/static/js/app.js#L2382)
interpolates extracted answers, question titles, and feedback into `innerHTML`.
Chromium rendered `Title with "quoted text"` as `Title with ` and executed an
image event handler supplied inside a textarea-closing OCR string. Saving can
persist the truncated title. The HTML report endpoint also interpolates unescaped
student names and feedback; a stored script tag was returned unchanged in a 200
response (report-browser execution was not separately tested). Use text/value
properties and context-appropriate escaping at both rendering boundaries.

### R11 [P1] Classroom release can send a grade to the wrong student

[`google_classroom.py:458`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/google_classroom.py#L458)
chooses the first coursework submission when the local student has no Google ID.
The email fallback only runs when the entire list is empty. In a mocked class,
Alice's email-backed local record patched and returned `BOB_SUBMISSION`, with no
profile lookup. Resolve the exact intended identity before listing/selecting work;
account for pagination and reject ambiguous or missing associations.

### R12 [P1] Single Classroom release bypasses teacher approval

[`google_classroom.py:396`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/google_classroom.py#L396)
checks linkage and credentials but not approval. A pending synthetic submission
completed the mocked upload/grade/return path. Bulk release filters approved work,
but the single release endpoint does not. Enforce approval and completeness in the
shared release operation before any external side effect.

### R13 [P1] Network/tunnel mode exposes teacher records and mutations without authentication

[`config.py:30`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/config.py#L30)
defaults to `0.0.0.0`. Routers and `/data/processed` have no access checks, and the
launcher explicitly offers a public Cloudflare tunnel. Anonymous report retrieval
and deletion return 200 in the isolated API probe. Other-device exposure depends
on network reachability or tunnel use; no live tunnel was opened. Default to
loopback and protect teacher APIs and script resources before exposing them.

### R14 [P1] A cold offline launch breaks core interface controls

[`index.html:13`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/static/index.html#L13)
and lines 35/37 load Tailwind, Chart.js, and Lucide only from CDNs. With external
requests blocked, real HTML/JS emitted undefined-library errors. All five panels
and hidden modals became visible because Tailwind's `.hidden` utility was absent;
navigation also threw. Bundle dependencies locally and test without a warm cache.

### R15 [P2] One student's question total rewrites the class assignment maximum

[`db.py:744`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/db.py#L744)
and the approval path update shared `assignments.max_marks` from the current
submission. After an 80/100 script, a partial five-mark extraction changed the
first student's report to 80/5 while its stored percentage stayed 80%. Keep the
scheme authoritative and validate each result against its assessment version.

### R16 [P2] Deleting records leaves student scripts retrievable

[`db.py:676`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/db.py#L676)
and bulk deletion paths delete SQL rows without owned assets. A script image
remained on disk and its old static URL returned 200 with identical content after
deletion. This contradicts the README's cleanup promise. Delete owned derived
images/reports, handle combined-scan references, and verify old URLs stop working.

### R17 [P2] Identity correction changes trusted roster records and unrelated history

[`db.py:713`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/db.py#L713)
updates the shared student's name/class when an existing code is detected or
entered for one script. Reproduced a single-script correction changing Alice's
roster and another submission to `Mallory OCR` / `Wrong Class`. Reassociate scripts
without overwriting trusted roster fields; make global roster edits explicit.

### R18 [P2] Chinese report text cannot be represented by the selected PDF fonts

[`report_generator.py:137`](https://github.com/String-sg/marking/blob/cca32d23d06a1e57ad1d193ae07b3418cfe95660/app/core/report_generator.py#L137)
uses Helvetica styles without registering a CJK font. A synthetic PDF lost all
Chinese name/title/feedback strings on text extraction, replacing them with `I`
glyphs. This establishes a font/encoding defect; visual print QA remains required.
Bundle/register an appropriate licensed font and verify both rendering and text.

## Additional gaps and validation limits

- Four existing cross-page science tests fail: scheme maximums for Q5(a)/5(c) and
  Roman subparts are not applied. These need correction alongside R03/R15; see the
  exploratory test summary and `test_cross_page_science_questions.py`.
- Scanned rubric parsing silently limits OCR to five pages, and mixed text/scanned
  PDFs can bypass OCR for scanned-only pages. These paths were code-inspected;
  focused synthetic document regression coverage is still needed.
- Direct-marking regeneration clears existing annotations before essay fallback
  consumes them. Preserve Step 2 evidence until a replacement is successfully
  committed; this path needs a focused failure/retry integration test.
- Existing Classroom tests write the configured credential file and disconnect
  the configured account without isolating paths. Run them only in a disposable
  checkout until test data/credential isolation is fixed.
- One test requires a private absolute Windows image path and two tests skip.
  Portable synthetic fixtures are needed before CI can be trusted.
- This repository has no committed CI workflow at the reviewed revision.
- No live OCR accuracy benchmark, Windows desktop run, mobile scan/tunnel test,
  or authorised Classroom round trip was performed. These remain release gates.
